# Dockerun 前端样式与交互规范

## 适用范围与依据

本规范约束本项目后续所有前端页面及公共界面组件，包括资源管理、应用发布、系统设置与账号页面。采用 Vue 3、TypeScript、Element Plus 和现有工作台布局；不为统一样式另换组件库。

基准页面是「容器」「网络」「卷」「外部仓库」「内置仓库」。用户提到的「外部容器」「内置容器」，在这份规范中对应现有的外部仓库与内置仓库页面，不另造业务概念。

遵循它们共同的深色、紧凑、清晰的管理工作台风格。统一的是视觉层级、信息密度、操作语义和反馈机制，不强制所有页面套用列表布局。用户后续明确调整规范时，以新要求为准并同步维护本技能。

- 修改外观、布局或组件时，按需阅读[视觉与布局规范](references/style-guide.md)的相关章节。
- 修改查询、导航、表单、异步操作或权限行为时，按需阅读[交互与中文规范](references/interaction-guide.md)的相关章节。
- 两份参考文档列出真实源码入口；具体业务能力与接口限制以当前代码和服务端校验为准。

## 必须保持的共同规则

### 全部用户界面使用简体中文

标题、导航、表头、按钮、占位文字、提示、状态、校验、通知、确认文案、空状态及无障碍名称都使用简体中文。本技能及后续新增的项目说明也使用中文。

代码标识符、接口字段、资源原始名称、路径、协议、品牌名、命令和日志原文保留原样。技术名词需要解释时采用「中文名称（原文）」；不要把资源值翻译成另一个名称。英文历史文案不是规范示例，修改相关界面时应一并调整为中文。

### 视觉基线

- 页面底色 `#151515`，卡片 `#202020`，输入框 `#171717`，表头 `#303030`；卡片细边框、`10px` 圆角。
- 正文以 `13px` 为主；页面标题 `18px / 600`，卡片标题 `15px / 600`，表头和操作 `12px`，次要信息 `11–12px`。
- 默认主操作采用浅色按钮：背景 `#eee`、文字 `#262626`。链接及焦点使用蓝色 `#35acd7` / `#33a7d5`；删除采用暗红色。不要把所有按钮改成高饱和蓝色。
- 桌面内容边距 `18px 20px`，模块间距 `16px`；窄屏内容边距与模块间距以 `12px` 为基准。
- 使用既有线性图标、低饱和状态标记、细分隔线。保持现有信息密度，不增加无业务作用的大横幅、装饰渐变、强阴影或大块留白。
- `design-system.css` 和通用旧组件中有历史样式；发生差异时，以这五类资源页面的共同风格及本规范为目标，不直接复制旧样式。

### 页面骨架

- 列表页：页面标题与刷新 → 列表卡片工具栏 → 筛选与摘要 → 就地反馈 → 可滚动表格 → 固定分页。
- 详情页：标题、返回与必要操作 → 分组卡片 → 键值信息和关联资源；复杂详情允许内容区纵向滚动。
- 创建/编辑页：基本信息 → 按业务划分的配置组 → 字段帮助与校验 → 取消及提交。
- 弹窗处理简短任务或确认；抽屉承载需要保留列表上下文的标签、版本等详情；长表单和独立工作区使用页面。

### 交互底线

- 搜索可清空，筛选有明确的「全部…」默认值，存在条件时提供「重置筛选」。先过滤、再排序、再分页。
- 查询条件或每页条数变化后回到第一页；数据变化后修正越界页码。分页或查询变化后表格滚动回顶部。
- 有详情/创建往返的列表保留搜索、筛选、排序与分页上下文；不要返回后无条件丢弃用户位置。
- 批量勾选只作用于当前页可操作项，正确显示半选、已选数量和清除入口。查询条件变化时清除旧选择，刷新时剔除失效项。
- 分别处理首次加载、刷新、无数据、无匹配、失败及局部数据不可用。刷新失败保留已有内容，并就地提供「重试」。
- 提交有加载状态并防重复；失败保留输入；危险操作说明具体对象和实际影响。部分成功时明确列出失败项，重试只针对失败项。
- 根据角色、资源状态、维护状态控制操作能力，并说明不可用原因；后端校验继续作为最终约束。不要为视觉一致新增不受支持的业务按钮。

## 实施方式

1. 确认当前页面类型和业务约束，读取最接近的基准页面、领域工具函数及接口。先辨别可复用的卡片、图标、操作组、弹窗和反馈模式。
2. 在本次页面范围内统一视觉与交互。页面级样式采用作用域或领域类名前缀；弹出层使用专属类名，实际检查传送到页面根部后的主题与尺寸。
3. 将筛选、排序、校验、状态判定等可复用逻辑放入 `frontend/src/utils/`，接口放入 `frontend/src/api/`；复用既有请求层与错误策略，避免重复通知。
4. 改动页面布局时，检查 `MainLayout.vue` 对应路由的内容区配置。列表需要完整的弹性布局链及局部滚动，长表单/详情需要正常纵向滚动。
5. 验证实际用户行为：默认界面、长名称、搜索/筛选、加载/失败/空状态、关键提交、返回上下文与窄屏。新增有业务意义的逻辑时补充适量测试；纯文案或间距调整不必新增测试。
6. 对代码变更执行相关测试、`pnpm run type-check` 和 `pnpm run build`。视觉改动检查桌面与窄屏渲染；若使用模拟接口或有验证限制，交付时明确说明。文档或技能本身的改动只做对应校验，不额外运行无关前端构建。

## 完成标准

- 页面可见文案及无障碍名称为中文，原始资源值和技术标识保持准确。
- 与五类基准页面的颜色、字级、间距、按钮语义和信息密度一致。
- 查询、分页、选择、导航、权限、提交和反馈相互一致，没有无效按钮、重复请求或伪造的成功状态。
- 长内容和窄屏不会撑破整页；关键操作完整可见，表头与分页可用，弹窗内容可滚动。
- 保留本次任务之外的既有改动；规范应用不等于授权顺带重写所有页面。
