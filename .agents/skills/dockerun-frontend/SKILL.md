# Dockerun 前端样式与交互规范

## 适用范围与依据

本规范约束本项目后续所有前端页面及公共界面组件，包括资源管理、应用发布、系统设置与账号页面。采用 Vue 3、TypeScript、Element Plus 和现有工作台布局；不为统一样式另换组件库。

基准页面是「容器」「网络」「卷」「外部仓库」「内置仓库」。用户提到的「外部容器」「内置容器」，在这份规范中对应现有的外部仓库与内置仓库页面，不另造业务概念。

遵循它们共同的深色、紧凑、清晰的管理工作台风格。统一的是视觉层级、信息密度、操作语义和反馈机制，不强制所有页面套用列表布局。用户后续明确调整规范时，以新要求为准并同步维护本技能。

- 修改外观、布局或组件时，按需阅读[视觉与布局规范](references/style-guide.md)的相关章节。
- 修改查询、导航、表单、异步操作或权限行为时，按需阅读[交互与中文规范](references/interaction-guide.md)的相关章节。
- 两份参考文档列出真实源码入口；具体业务能力与接口限制以当前代码和服务端校验为准。

## 必须保持的共同规则

### 全部用户界面使用简体中文

标题、导航、表头、按钮、占位文字、提示、状态、校验、通知、确认文案、空状态及无障碍名称都使用简体中文。本技能及后续新增的项目说明也使用中文。

代码标识符、接口字段、资源原始名称、路径、协议、品牌名、命令和日志原文保留原样。技术名词需要解释时采用「中文名称（原文）」；不要把资源值翻译成另一个名称。英文历史文案不是规范示例，修改相关界面时应一并调整为中文。

### 视觉基线

- 页面底色 `#151515`，卡片 `#202020`，输入框 `#171717`，表头 `#303030`；卡片细边框、`10px` 圆角。
- 正文以 `13px` 为主；页面标题 `18px / 600`，卡片标题 `15px / 600`，表头和操作 `12px`，次要信息 `11–12px`。
- 默认主操作采用浅色按钮：背景 `#eee`、文字 `#262626`。链接及焦点使用蓝色 `#35acd7` / `#33a7d5`；删除采用暗红色。不要把所有按钮改成高饱和蓝色。
- 桌面内容边距 `18px 20px`，模块间距 `16px`；窄屏内容边距与模块间距以 `12px` 为基准。
- 使用既有线性图标、低饱和状态标记、细分隔线。保持现有信息密度，不增加无业务作用的大横幅、装饰渐变、强阴影或大块留白。
- `design-system.css` 和通用旧组件中有历史样式；发生差异时，以这五类资源页面的共同风格及本规范为目标，不直接复制旧样式。

### 页面骨架

- 列表页：页面标题与刷新 → 列表卡片工具栏 → 筛选与摘要 → 就地反馈 → 可滚动表格 → 固定分页。
- 详情页：标题、返回与必要操作 → 分组卡片 → 键值信息和关联资源；应用、部署记录及其关联的仓库、镜像、容器、网络、卷详情统一采用固定顶部栏，标题、返回、刷新、已有状态和页面级操作始终可见，仅下方内容滚动。复用 `WorkspaceEditor`，通过路由 `meta.workspaceEditor` 关闭外层重复滚动。分组配置和资源行操作放在对应卡片或行内。
- 应用详情按「部署环境」「发布版本」「应用配置」切换，同一视图只展示一个主列表。列表视图不滚动整页，只有表格内容滚动，标题、视图切换、工具栏和分页固定可见；长说明及操作指引放入配置视图。首次创建使用紧凑步骤及明确的下一步入口，随实际环境和发布状态更新，不能用大块说明挤占列表。
- 创建/编辑页：复用固定顶部栏，左侧后退箭头与标题，右侧创建/保存等主要操作及已有状态；下方基本信息和分组配置限宽居中并独立滚动，上下留白一致。网络、卷及仓库创建/编辑页沿用同一规则，按钮移到表单外仍保留原表单校验与回车提交。
- 发布工作区、从模板创建应用等独立长表单：编辑区限宽并水平居中；标题、返回、刷新及创建/保存/发布等操作放在固定顶部栏；有步骤导航时也放在顶部，只有中间表单滚动。滚动区上下留白相等，具体尺寸及结构见视觉与布局规范。
- 应用发布采用「部署内容、运行参数、前后置脚本、高级配置」独立标签页，默认进入部署内容，代替强制四步向导。工作区填满剩余宽度与高度，环境、目标摘要、标签页与保存/预览/确认操作固定在顶部；各页共用草稿，切换不保存、不丢失修改，标签显示参数数量、脚本配置状态、未保存和校验错误。部署内容、前后置脚本及预览使用弹性大编辑器，长代码只在编辑器内部滚动；参数和高级表单在各自面板内滚动，不能用固定最小高度或估算视口高度撑开整个页面。文件标签在自身区域横向滚动，长文件名不挤占编辑区域；切换文件保留原始内容、光标、滚动和撤销记录。保存配置不执行任务，预览校验全部标签页，确认后才提交不可变执行快照。
- 应用详情提供「编辑部署配置」入口，保存后供后续手动和自动创建的新版本使用，不立即部署，不改写历史版本或已提交任务。发布版本提供「基于此版本编辑」，完整复制部署内容、配置文件、执行设置和应用附加脚本为独立草稿；「部署此版本」明确说明可部署到其他环境或重新部署历史版本，进入专用只读部署视图：仅可选择环境，展示版本及目标环境的已保存信息，部署内容与配置文件按需展开；隐藏部署编辑标签、版本切换、保存配置、参数修改及添加文件等编辑控件，沿用预检查与确认部署，不保存配置。自动发布在环境行及应用配置中提供直接入口，独立保存监听规则及明确填写的容器关联与替换策略，不连带更新主机、运行参数、脚本或恢复策略；命令部署通过 DOCKERUN_IMAGE 使用触发镜像，配置时明确提示引用方式。
- 项目所有可编辑的脚本、Compose、Dockerfile 与代码配置文件统一复用 `CodeEditor`，根据文件类型注册并启用对应语法高亮，未知类型回退纯文本；说明和只读日志不强行改成代码编辑器。普通长表单中的编辑器使用较大的有界区域，独立编辑页和脚本编辑弹窗填满剩余空间，工具栏及保存/取消固定可见，编辑器本体内部滚动，不能产生页面溢出。脚本及代码提供放大编辑，在可调整大小的对话框中编辑同一草稿，只读内容提供放大查看。部署任务、环境、版本优先显示业务名称，编号作为辅助定位信息。
- 环境配置及自动发布配置通过「关联容器」明确作用范围，命令部署提供「部署时由系统替换关联容器」，显示停止并删除、清理同 tag 引用、拉取及执行脚本的实际顺序，并说明保留数据卷及失败不会恢复旧容器。预览只读展示关联范围与替换策略，确认前配置变化须重新预览。应用环境列表展示实际运行镜像及短 Image ID，配置视图按环境和主机列出完整引用、Image ID、状态与核对时间；只展示 Docker 核对或 Agent 上报的信息，缺失或失败不能推测正在运行的镜像。
- 环境配置默认展示环境名称、统一的部署目标和运行参数；部署目标兼容单台与有序多台主机，单机模板仍限制为一台。普通应用和模板应用的运行参数统一使用「名称、值、删除」键值对表单，不要求填写 JSON；模板定义的名称固定，保留必填标记、类型校验、密码生成及派生端口提示，附加参数可增删，敏感值默认隐藏。自动发布独立分组并提供专用配置入口；高级配置中的「附加脚本来源」使用「使用版本中的应用附加脚本」「使用此环境的独立附加脚本」「不执行附加脚本」，明确其不影响主部署命令及部署检查；脚本及恢复策略放入默认收起的高级配置；折叠只改变展示，不清空配置，也不计入未保存修改。
- 从模板创建应用与发布向导复用同一键值对编辑器。模板创建保留模板定义的参数范围、必填和类型校验、仓库镜像切换及密码生成；发布向导的容器环境变量和目标环境运行参数均可编辑。目标参数支持单独保存及预检查前自动保存，只更新参数；切换环境或刷新保留各环境草稿，未保存修改继续保护。已有版本部署使用目标环境当前已保存的运行参数，只读展示且不自动补填或保存；预检查和确认部署校验参数是否与已确认值一致。参数行的界面编号不计入未保存判断或版本准备标识。
- 发布向导的非敏感配置文件使用文件表单，支持添加文件、编辑文件名及内容、删除文件与放大编辑，不要求填写 JSON。模板配置逐项回填；文件名位于 configs/ 下，校验重复、目录冲突及无效路径，内容和空文件按原文保留。文件行的界面编号及排列顺序不计入未保存判断或版本准备标识。
- 弹窗处理简短任务或确认；抽屉承载需要保留列表上下文的标签、版本等详情；长表单和独立工作区使用页面。

### 交互底线

- 搜索可清空，筛选有明确的「全部…」默认值，存在条件时提供「重置筛选」。先过滤、再排序、再分页。
- 查询条件或每页条数变化后回到第一页；数据变化后修正越界页码。分页或查询变化后表格滚动回顶部。
- 有详情/创建往返的列表保留搜索、筛选、排序与分页上下文；不要返回后无条件丢弃用户位置。
- 二、三级页面标题左侧统一使用后退箭头，复用用户指定的 SVG；箭头优先返回有效站内来源页，无可用历史时返回业务父级。面包屑各上级可点击，当前页为文本，窄屏也保留导航入口。创建或发布提交成功后替换已提交的表单历史记录。
- 批量勾选只作用于当前页可操作项，正确显示半选、已选数量和清除入口。查询条件变化时清除旧选择，刷新时剔除失效项。
- 分别处理首次加载、刷新、无数据、无匹配、失败及局部数据不可用。刷新失败保留已有内容，并就地提供「重试」。
- 提交有加载状态并防重复；失败保留输入；危险操作说明具体对象和实际影响。部分成功时明确列出失败项，重试只针对失败项。
- 创建、编辑和发布页存在未保存修改时，后退、面包屑、切换菜单及浏览器离开均需确认放弃；继续编辑保留输入和位置。初始默认值、加载回填、改回原值及保存成功不误报，保存失败继续保护。复用 `useUnsavedChanges`；编辑弹窗通过 `FormDialog` 的 `draft` 接入，自定义编辑弹窗也需保护关闭与取消。同页独立表单分别记录基线，保存一项不清除另一项的修改状态。
- 根据角色、资源状态、维护状态控制操作能力，并说明不可用原因；后端校验继续作为最终约束。不要为视觉一致新增不受支持的业务按钮。

## 实施方式

1. 确认当前页面类型和业务约束，读取最接近的基准页面、领域工具函数及接口。先辨别可复用的卡片、图标、操作组、弹窗和反馈模式。
2. 在本次页面范围内统一视觉与交互。页面级样式采用作用域或领域类名前缀；弹出层使用专属类名，实际检查传送到页面根部后的主题与尺寸。
3. 将筛选、排序、校验、状态判定等可复用逻辑放入 `frontend/src/utils/`，接口放入 `frontend/src/api/`；复用既有请求层与错误策略，避免重复通知。
4. 改动页面布局时，检查 `MainLayout.vue` 对应路由的内容区配置。列表需要完整的弹性布局链及局部滚动，长表单/详情需要正常纵向滚动。
5. 验证实际用户行为：默认界面、长名称、搜索/筛选、加载/失败/空状态、关键提交、返回上下文与窄屏。新增有业务意义的逻辑时补充适量测试；纯文案或间距调整不必新增测试。
6. 对代码变更执行相关测试、`pnpm run type-check` 和 `pnpm run build`。视觉改动检查桌面与窄屏渲染；若使用模拟接口或有验证限制，交付时明确说明。文档或技能本身的改动只做对应校验，不额外运行无关前端构建。

## 完成标准

- 页面可见文案及无障碍名称为中文，原始资源值和技术标识保持准确。
- 与五类基准页面的颜色、字级、间距、按钮语义和信息密度一致。
- 查询、分页、选择、导航、权限、提交和反馈相互一致，没有无效按钮、重复请求或伪造的成功状态。
- 长内容和窄屏不会撑破整页；关键操作完整可见，表头与分页可用，弹窗内容可滚动。
- 保留本次任务之外的既有改动；规范应用不等于授权顺带重写所有页面。
