# Dockerun UI 规范

参考已查看的本地 Portainer 暗色布局，继续使用 Vue、Element Plus 与通用组件。目标是让镜像交付、环境选择和部署结果清楚可见。

## 视觉基础

| 元素 | 约定 |
|---|---|
| 页面 | `#191c20` |
| 侧栏 / 顶栏 | `#22252a` |
| 卡片 | `#25282d`，细边框 `#343941` |
| 链接 / 选中 / 焦点 | 青蓝 `#38bdf8`，选中浅色块及左边线 |
| 正文 | 14px，本地系统字体 |
| 引用、ID、日志 | 本地等宽字体 |
| 状态 | 文字、圆点图标与颜色共同表达 |
| 主操作 | 高对比实色按钮；次操作描边；危险操作红色 |

实现集中在 `frontend/src/styles/workspace.css`，基础组件继续使用 `design-system.css`。编辑器及 worker 在本地构建、按需加载；没有字体或编辑器 CDN 请求。

## 导航与布局

管理员导航分三组：发布工作区（概览、应用、记录、发布包）、镜像与资源（内置 / 外部仓库、本机镜像、容器、网络、卷）、系统管理（用户、主机、维护、Webhook、系统设置、历史脚本、个人账号）。普通用户仅有内置仓库和个人账号，未授权时显示原因；后端同步拒绝越权请求。

可折叠侧栏、顶部面包屑、账户与角色标识、内容卡片和紧凑列表。约 1100px 以下默认折叠；更窄窗口保留图标导航。环境和主机使用不同字段，不能把 test / prod 显示为主机名。

大表单、导入和 Compose 编辑在独立页面；创建用户、环境等小表单使用对话框。错误在页面内持续保留，对话框内也能看见失败原因。密码与令牌不进入生成命令。

## 本地镜像

本地镜像页参照 Portainer Images 的深灰卡片、紧凑工具栏、蓝色标签与 SVG 图标。顶部保留镜像拉取表单，列表只有多选、ID、标签、大小和创建时间五列。列表填满工作区剩余高度，表头固定，只有列表主体滚动，操作与底部分页始终可见。

支持 ID / 标签 / 摘要搜索、列排序、跨页选择、普通或强制删除、本页上传导入，以及所选镜像合并导出为一个 tar 并保留原标签。搜索变化时清除选择；刷新时剔除已不存在的选择；删除部分失败时保留失败项与错误并支持重试。拉取和导入解析实际进度流，只有收到完成标记才显示成功，流中错误或中断均保留失败信息。

ID 可点击进入独立镜像详情，返回时保留搜索、排序及分页。没有任何容器引用的镜像在 ID 旁显示橙色“未使用”标记；判断使用不可变的镜像 ID，并包含已停止的容器。容器信息读取失败或引用信息不完整时不误标未使用。

详情沿用 Portainer 的标签、添加标签、镜像信息、Dockerfile 配置和镜像层卡片。展示完整 ID、大小、创建时间、平台、使用状态、摘要、Labels、CMD、ENTRYPOINT、端口、环境变量与可用的用户、工作目录、数据卷和健康检查配置；镜像层使用 Docker 真实历史，支持排序和展开长指令。各区加载失败独立呈现，保留基本信息；删除需确认，导出沿用镜像列表接口。

## 发布流程

`选择来源 → 应用与环境 → 参数配置 → 预检查与差异 → 执行部署`

镜像来源在发布工作区的「部署内容」中选择。命令部署支持由脚本准备镜像、离线镜像归档及完整包中的镜像，离线包直接上传并在校验完成后选中；Compose 支持镜像地址、已配置仓库、本机镜像和完整发布包。高级配置可保存关联容器及替换策略，首次插入 docker run 示例时关联 $APP_NAME 并开启替换。后续手动及历史版本部署先准备镜像再替换容器，不清理镜像；自动发布仅清理已存在且可删除的触发 tag 引用。使用已有版本时保持脚本和镜像身份，只选择目标环境确认部署。

上传、文件校验、镜像加载和部署分别呈现状态。导入完成只是材料可用，不显示“部署成功”。任务页面独立查询历史状态和增量日志；浏览器关闭不会取消任务。组发布展示每个目标的任务、版本、健康和结果，失败暂停后续目标。

未配置健康检查时使用“已启动，未验证健康”。失败、恢复失败、需要核对与取消均有独立文字，不能只变颜色。禁用的恢复选项由“无状态应用”条件约束；生产自动发布由管理员显式开启并指定允许推送人。

## 验收

检查 1280、1440、1920 和约 1000px 的内容可达性；键盘完成来源选择、输入与提交，焦点可见。核对普通用户菜单与 API 能力一致，离线加载所有本地资源，保留输入及错误。浏览器已验证基本布局与创建流程；完整尺寸、角色和断网端到端矩阵记录在路线图中。
