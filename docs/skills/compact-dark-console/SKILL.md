# 紧凑深色工作台

将 Dockerun 资源管理页面的共同视觉与交互提炼为可跨项目使用的规范。目标是让数据清晰、操作随手可用、失败可恢复、上下文不丢失。适合管理后台、资源控制台与配置工作台。

## 应用范围

用户选择本风格后，在当前任务范围内应用；已有项目采用渐进调整，新项目先建立主题与页面骨架。沿用目标项目的框架、组件库、路由、请求层和业务权限，不为采用本技能进行技术栈迁移或重写无关页面。

默认界面文案与无障碍名称使用简体中文；目标项目明确的语言、品牌、可访问性与产品要求优先。资源名称、品牌、协议、接口字段、路径、命令和日志原文保持准确。

本技能不包含 Docker 业务限制，不要求目标项目存在任何 Dockerun 源码或同名组件。删除、维护、权限、发布等能力由目标系统实际接口决定。

## 识别这套风格的核心规则

- **深灰分层**：页面 `#151515`、卡片 `#202020`、输入与代码区 `#171717`、表头与分隔 `#303030`；卡片以细边框和 `10px` 圆角区分。
- **紧凑且有层级**：正文 `13px`，页面标题 `18px / 600`，卡片标题 `15px / 600`，表头与操作 `12px`。桌面边距 `18px 20px`、模块间距 `16px`，窄屏以 `12px` 为基准。
- **动作有明确语义**：主要提交使用浅底深字按钮（`#eee` / `#262626`），链接与焦点用蓝色，删除用暗红色。不要让组件库的默认高饱和主色覆盖这一层级。
- **操作始终可见**：独立详情、创建、编辑和向导将返回、标题、状态、刷新与主要动作放在固定顶部区，只有下方内容滚动。列表让表格局部滚动，保留工具栏与分页。
- **保持工作位置**：详情往返保留合法查询、排序和分页；有效站内来源优先，直接访问有业务父级回退；创建成功替换已提交表单的历史记录。
- **保护用户输入**：修改后离开需确认；失败保留输入；保存成功才更新草稿基线。取消放弃确认继续停留，普通可逆保存不增加重复确认。
- **如实表达异步结果**：首次加载、刷新、真实为空、无匹配、失败和局部不可用分别处理；刷新失败保留旧数据，未知不冒充零或正常。
- **批量结果逐项处理**：当前页全选只覆盖可操作项，显示总已选数量；部分成功列出失败对象与原因，重试只包含失败项。

## 实施流程

1. 查看目标项目的约束、主题入口、最接近的页面、公共组件与接口，确定本次页面类型及真实能力。已选用本规范时直接实施常规映射，不反复要求用户确认颜色或布局。
2. 按需读取参考文件，复用已有组件；缺少公共能力时围绕当前需求提取主题、页面骨架、反馈、草稿保护或操作能力判定。
3. 将视觉变量映射到现有样式系统。主题限定在采用本风格的工作区；弹出到根节点的浮层也要获得相同主题。不得将示例选择器变成影响全站的无作用域覆盖。
4. 按相关交互契约实现查询、导航、提交、权限与失败恢复。客户端和服务端分页保持真实语义，不添加接口不支持的按钮。
5. 验证本次涉及的用户行为与桌面、窄屏布局。代码改动运行目标项目相应检查；仅整理规范时验证技能元数据、引用和示例，不运行无关构建。

## 完成检查

- 字体、间距、色彩与按钮语义一致；长名称和错误信息有完整读取方式。
- 顶部操作、表头、分页与弹层底部操作在窄屏和较矮视口可用；页面没有重复滚动或整页横向溢出。
- 查询变化回到第一页，数据变化修正越界页码，详情返回保留上下文。
- 首次加载与刷新、空与失败、未知与零明确区分；没有伪造成功或重复报错。
- 提交防重复，失败保留输入，草稿离开保护覆盖实际导航与弹层关闭入口。
- 批量结果、权限和禁用原因符合业务；键盘焦点、图标名称、排序与选择语义可用。
